# game/

The client application: a Minecraft‑style voxel sandbox. Depends on the engine (`src/mge`); nothing
in the engine depends on it except the `mge::createApplication()` definition. The voxel machinery
(chunks, world, meshing) lives in the engine module [`mge_voxel`](../src/mge/voxel/README.md); the
game only says **which blocks exist** and **what the terrain looks like**.

| File | Contents |
|------|----------|
| `SandboxApp.cpp` | `SandboxApp : mge::Application` (game loop callbacks, chunk streaming, GPU meshes) and `mge::createApplication()` |
| `SandboxBlocks.h/.cpp` | `sandbox::SandboxBlocks` (ids) and `registerSandboxBlocks(registry)`: 20 blocks, each with atlas tiles **and** a flat colour; atlas constants (`kWaterTile`, `kLavaTile`) |
| `SandboxTerrain.h/.cpp` | `sandbox::SandboxTerrain : mge::TerrainGenerator`: noise terrain (fbm + ridged mountains), biomes (plains, desert, mountains, shore), caves, trees (crossing chunk borders) and flowers; `TerrainSettings`, `Biome` |

Game code lives in namespace `sandbox`.

CMake (`game/CMakeLists.txt`):
- `sandbox_world` is a static lib (SandboxBlocks, SandboxTerrain) that links only `mge_voxel`, so it
  is **headless**. It is tested by `tests/game/` and used by `examples/headless_smoke`.
- `mge_add_game(sandbox …)` creates the exe (written to the build dir root), the `run` /
  `run-sandbox` targets, and the 120‑frame offscreen smoke test.

Include as `#include <game/SandboxTerrain.h>`.

## `SandboxApp`

### Members
| Member | Type | Role |
|--------|------|------|
| `m_gpu` | `GpuModule*` | Device and frame (SDL3 GPU, Vulkan) |
| `m_renderer` | `unique_ptr<MeshRenderer>` | Draws the chunks (engine shaders, embedded) |
| `camera` | `mge::Camera3D` | Player view, created 1280×720, starts at (0, 25, 0) |
| `m_registry`, `m_blocks` | `BlockRegistry`, `SandboxBlocks` | Block catalogue and the sandbox's ids |
| `m_world` | `mge::VoxelWorld` | Loaded chunks (CPU), generated by `SandboxTerrain` |
| `m_gpuChunks` | `std::map<ChunkCoord, GpuChunk>` | GPU meshes per chunk (`GpuMesh` opaque / transparent, empty when the chunk has no such faces), cleared in `onShutdown` |
| `m_atlas` | `Texture2D` | `Minecraft-like_3d_tileset.png`, with a CPU copy for the water/lava animation |
| `m_fpsFrames`, `m_fpsElapsed` | `int`, `float` | Average FPS written to the Debug log every 5 s (the TTF HUD was removed in #9) |
| `m_waterFrames` / `m_lavaFrames` | `vector<int>` | `{205,206,207,222,223}` / `{237,238,239,254,255}` atlas tiles |
| `m_animTimer`, `m_currentAnimFrame` | | 0.2 s per animation frame, on unscaled time |
| `m_isPaused`, `m_mouseCaptured` | `bool` | Pause state; `m_mouseCaptured` is always true |

### Construction
`SandboxApp()` passes an `ApplicationConfig` (title "miniGameEngine - Sandbox", 1280×720) and adds
`PlatformModule` (window without OpenGL), `GpuModule` (SDL3 GPU) and `AudioModule`, in that order.
CMake modules: `platform gpu graphics audio render`. `render` is only for the legacy `Camera3D`,
until #32/#40.

### `onInit` (returns false → clean exit with code 1)
0. Keep a pointer to `PlatformModule`, register `handleWindowEvent` (resize/focus) and bind the controls (`bindControls`).
1. Create the `MeshRenderer` with the swapchain format; it fails cleanly if the pipelines can't be created.
2. Set the camera position (spawn above the terrain) and install the **collision callback**: convert
   the AABB corners to blocks with `blockAt` (`floor`) and return true if any block in range is
   solid (`m_world.isSolid`).
3. Load the atlas (`Texture2D::fromFile(…, keepCpuCopy)`; all asset paths go through `mge::assetPath`).
4. Lock the cursor.
5. Log the controls (Info).

### Controls (`bindControls` → `ActionMap`)
| Action / axis | Binding |
|---------------|---------|
| `MoveForward` axis | W / S |
| `MoveRight` axis | D / A |
| `MoveUp` axis | Space / Left Shift |
| `Sprint` | Left Ctrl |
| `Pause` | P |
| `Quit` | Esc |
| `CaptureMouse` | Left mouse button |

`handleActions()` (start of `onUpdate`) handles Quit, CaptureMouse and Pause with `wasActionPressed`.
`cameraInput()` builds the camera's `CameraInput` from the axes, Sprint, and the mouse delta (only
while the cursor is locked).

### `handleWindowEvent(const SDL_Event&)` (platform event callback)
| Event | Action |
|-------|--------|
| Window resized | `camera.updateProjection` (listens to `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED`, so HiDPI is correct). The swapchain and the renderer's depth buffer follow the new size on their own |
| Focus gained (not paused) | Re‑lock cursor |

### `onUpdate(dt)` (`dt` = scaled frame time, 0 while paused)
1. Use `dt` for the camera.
2. Every 0.2 s of unscaled time (`time().unscaledDelta()`): `copyTile(m_waterFrames[i % 5], kWaterTile)`
   and the same for lava into `kLavaTile`. `copyTile` uses `Texture2D::copyFromOriginal`, copying
   32×32 tiles of the original image.
3. `streamChunks()`:
   - load (generate) every chunk column (4 chunks tall) within `kRenderDistance + 1` = 5 of the camera chunk;
   - mesh every **dirty** chunk within `kRenderDistance` = 4 (9×9 = 81 chunks) with
     `buildChunkMesh`, upload it (`device.uploadMesh`) and clear the dirty flag. Loading a chunk
     dirties its loaded neighbours, so meshes always match the data.

   The extra ring means borders are meshed against real neighbours. Everything is synchronous.
   The time taken is logged: Info for the first load (startup), Debug afterwards.
4. `camera.update(deltaTime)`.

### `onShutdown`
Releases the GPU meshes, the atlas and the renderer while the GPU device still exists. The
`GpuModule` shuts down afterwards.

### `onRender`
Skips the frame if `GpuModule::frame()` is null (minimised window). Otherwise:
1. `m_renderer->begin` clears to sky blue.
2. Camera = `depthZeroToOne(projection) * view`.
3. **Opaque** pass, then **transparent** pass (`MeshPass::Transparent`: blending, no depth writes).
   Both only draw chunks whose bounds pass `camera.isAabbVisible` (frustum culling), with
   `model = translate(chunkOrigin)` and the atlas.
4. `end`, then the FPS log every 5 s.

See `docs/ARCHITECTURE.md` §6.

## World layout

- **64 blocks tall:** `kWorldChunksY = 4` vertical chunks (y = 0..63). The sandbox loads whole
  chunk columns `(cx, 0..3, cz)`.
- The generator works in world Y, so any `cy` is valid: y ≤ 0 is solid stone, and above the world
  there is nothing.
- Block `(x, y, z)` occupies `[x, x+1)³`, and chunk `(cx, cy, cz)` starts at block `(cx*16, cy*16, cz*16)`.
- **Spawn:** the camera starts at `(0.5, max(surface, water) + 2.5, 0.5)`, above the terrain.

## `SandboxTerrain` – generation (noise, #27)

`SandboxTerrain(blocks, TerrainSettings{seed = 1337, caves = true})`. Everything comes from the
seed, so the same seed gives the same world on every machine.
- **Noise fields:** six `mge::Noise` instances (seed + 0..5) for height, mountains, temperature,
  moisture and two cave fields.
- **Randomness:** `mge::Pcg32` per column, seeded with `hash2i(wx, wz, seed)`. Stream **1** is
  used for terrain and stream **2** for decoration, with no global state.

Each column's height, biome and blocks come from a pure function, `column(wx, wz)`, so any chunk
can recompute any column. Within one `generate()` call they are computed once for the chunk plus
the tree margin.

**Height** (`surfaceHeight(wx, wz)`, `kWaterLevel = 20`):
- `24 + hills * 10 + mask * ridges * 30`, clamped to [1, `kMaxSurfaceHeight` = 56]:
  - `hills`: simplex fbm, 5 octaves, frequency 0.008;
  - `mask`: smoothstep(0.1, 0.5) of a very low‑frequency fbm (0.0025). It decides where mountains
    exist;
  - `ridges`: ridged simplex, 4 octaves, 0.012.
- Result: rolling hills, lakes and seas below 20, and mountain ranges up to ~56.

**Biomes** (`biome(wx, wz)`):

| Biome | When | Surface / below |
|-------|------|-----------------|
| Shore | height ≤ water + 1 | sand / sand |
| Mountains | mask > 0.3 and height > water + 14 | stone (15 % gravel) / stone |
| Desert | temperature > 0.1 and moisture < 0 (both: fbm, 3 octaves, 0.003) | sand / sand |
| Plains | otherwise | grass (5 % gravel, 0.5 % lava pool) / dirt |

**Pass 1, terrain** (world y):
- `y ≤ 0`: Stone (the floor, never carved).
- `y > height`: Water if `y ≤ 20`, else Air.
- Cave → Air (below).
- `y == height`: the surface block.
- The 3 layers below the surface: filler. Deeper: Stone.

**Caves** (`isCave`, on by default):
- Tunnels form where two 3D simplex fields (frequency 0.045 horizontal, 0.07 vertical) are **both**
  within ±0.09 of zero. This is the intersection of two "sheets", which gives worm‑like tunnels.
- Caves only carve y in [1, height − 4]. The floor and the 3 layers under the surface stay intact,
  so no holes to the void or to the surface, and no flooding.

**Pass 2, decoration** (Plains grass only): one `range(0,100)` roll gives 2 % tree (height
`range(4,6)`), 2 % Rose, 2 % Flower.
- The pass also visits the columns up to `kTreeRadius = 2` blocks **outside** the chunk, in world
  order (x, then z). Their trees can reach into this chunk.
- Columns whose trees can't reach this chunk's Y range are skipped.
- Every chunk replays the same events in the same order, so where two trees touch, the result is
  identical whichever chunk generates it.

**Trees:**
- The trunk is Log.
- The canopy is Leaves: a diamond with Manhattan distance < 4, 4 layers from `y+h-2` to `y+h+1`,
  written only into air.
- Each chunk writes the part of the tree that falls inside it, so trees **cross chunk borders
  intact**, also vertically (KI#6, fixed in #26).

**Cost.** Startup generates 484 chunks (11×11 columns × 4) in ~175 ms and meshes and uploads 324
in ~130 ms (Release, this machine; the sandbox logs it).

**Tests** (`tests/game/test_sandbox_terrain.cpp`) cover:
- determinism and the seed;
- height range (seas and mountains exist);
- every biome above 2 % of a 6 000² area;
- block rules (floor never carved, water only above the surface and ≤ 20);
- cave rate, with caves off meaning none;
- decoration at 1–3 % of grass columns;
- trees across borders and load‑order independence.

History: #5 fixed a bug where both passes reused one `srand` seed, so trees and roses never spawned.

## Blocks (`SandboxBlocks`)

| Rule | Blocks |
|------|--------|
| **Not solid** (walk through), not opaque | Rose, Flower, Sapling, Cobweb (shape `Cross`), Water, Lava |
| Solid but **not opaque** (transparent mesh) | Glass, Leaves |
| Solid, opaque cubes | everything else |

Atlas `Minecraft-like_3d_tileset.png`: 512×512, 32 px tiles, 16 columns; index = row*16 + col from the top‑left.

| Block | Tile(s) |
|-------|---------|
| grass | top 0, bottom 2, sides 3 |
| dirt | 2 |
| stone | 1 |
| planks | 4 |
| refined_stone | top/bottom 6, sides 5 |
| brick | 7 |
| tnt | top 9, bottom 10, sides 8 |
| cobweb | 11 |
| rose | 12 |
| flower | 13 |
| sapling | 15 |
| cobblestone | 16 |
| coal | 17 |
| sand | 18 |
| gravel | 19 |
| log | top/bottom 21, sides 20 |
| glass | 49 |
| leaves | 52 |
| water | 207 (animated: 205, 206, 207, 222, 223) |
| lava | 239 (animated: 237, 238, 239, 254, 255) |

Every block also has a flat `color`, so the world can be meshed **without the atlas** (the
procedural path; e.g. OBJ export). The legacy GL renderer doesn't upload vertex colours yet (KI#13, M3).

Blocks registered but never generated: planks, refined_stone, brick, tnt, cobweb, sapling,
cobblestone, coal, glass.

### Adding a block
1. Add an id field to `SandboxBlocks` and register it in `registerSandboxBlocks`, giving it tiles
   and/or a colour, solidity, opacity and shape.
2. Place it in `SandboxTerrain::generate` (or set it at runtime with `VoxelWorld::setBlock`).
